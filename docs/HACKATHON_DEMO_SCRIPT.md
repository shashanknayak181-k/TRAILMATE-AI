# Hackathon demonstration script (5–7 minutes)

## 1. State the problem (30 seconds)
Travellers can plan a trip, but a cancellation or unavailable stop can invalidate the plan. TrailMate AI demonstrates how to compare alternatives and review a revised itinerary before accepting it.

## 2. Sign in and explore (60 seconds)
- Sign in with a demo account.
- Search or filter the available destinations.
- Select a destination and move into planning.
- State clearly which destination data is curated demo data and which place results come from OpenStreetMap.

## 3. Create and save a trip (90 seconds)
- Choose a starting point, destination, travel date, traveller count, and budget.
- Add stops on the map if needed.
- Explain that the cost summary is a known-cost estimate/subtotal, not a guaranteed quote.
- Save the trip and open the saved-trips view to demonstrate persistence.

## 4. Start the trip and record progress (60 seconds)
- Start the saved trip.
- Mark one itinerary segment completed.
- Show that the saved status changes.

## 5. Demonstrate recovery (120 seconds)
- Open Recovery Lab for the same trip.
- Select a clearly labelled simulated disruption.
- Generate alternative plans.
- Compare rationale, estimated cost, and extra time.
- Explain that unknown costs prevent an unsupported claim of budget feasibility.
- Accept a feasible alternative and show the saved itinerary/history update.

## 6. Close with limitations (30 seconds)
Be explicit: disruption is simulated; routing depends on the public OSRM service; place search uses Nominatim; satellite imagery is Esri; live traffic, verified closures, weather, booking, and real transport status are not connected.

## Demo hygiene
- Use a disposable demo account and a fresh sample trip.
- Confirm backend and frontend terminals are running before presenting.
- Test the entire flow once immediately before the event.
- Keep a short screen recording as a fallback, but label it as a recording.
